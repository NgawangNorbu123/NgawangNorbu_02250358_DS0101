# Theory
Docker is a tool that packs an application and everything it needs into a single, portable container. This ensures the application runs exactly the same way on any computer.

Unlike Virtual Machines (VMs), containers do not need their own full operating system. Instead, they share the host computer's system, making them much faster and lighter on memory and CPU. Docker works on a client-server model, where the Docker user (client) talks to the background service (Docker Engine) to manage containers.

# Key Concepts
Docker Image: A ready-to-use template (like a blueprint) for creating containers.

Docker Container: A live, running instance of an image.

Dockerfile: A text script with instructions to build a Docker image.

Docker Hub: An online library used to save and share Docker images.

# Procedure
Step 1: Download Docker Desktop for Windows or Mac from docker.com.

Step 2: Run the installer. (Windows users should enable WSL 2 if asked).

Step 3: Open Docker Desktop and wait for the engine to start.

Step 4: Verify the installation by running docker --version in the terminal.

Step 5: Test it by running docker run hello-world to pull and run a test container.

Step 6: Download the Nginx web server image using docker pull nginx.

Step 7: Run Nginx in the background with docker run -d -p 8080:80 nginx, then visit http://localhost:8080 in a browser.

Step 8: See all running containers using docker ps.

Step 9: Stop a container using docker stop <container_id>.

# Purpose of Docker
Docker fixes the "it works on my machine" problem. By packaging code together with its dependencies, applications run reliably anywhere. It helps teams deploy software faster, saves system resources compared to traditional VMs, and is a core tool for modern microservices and DevOps.
