# Building a Docker Image for an Application
# Aim & Objectives
To learn how to package a web application into a portable Docker image using a custom Dockerfile.

Understand the difference between Docker images and containers.

Write a standard Dockerfile for a Python Flask application.

Build a custom Docker image using CLI commands.

Run and verify the application inside a container.

# Theory
Docker allows developers to ship and run applications within containers.

Docker Image: A read-only, unchanging template that bundles the application code, runtime, system tools, libraries, and settings together.

Dockerfile: A simple text script containing sequential commands used to automatically build a Docker image.

Docker Container: A live, running instance of an image.

# Source Code
1. Application Script (app.py)
Python
from flask import Flask

app = Flask(__name__)

@app.route('/')
def home():
    return "<h1>Flask App Running inside Docker!</h1><p>Question: What is your name?</p>"

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=5000)
2. Configuration Script (Dockerfile)
Dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY . .
RUN pip install flask
EXPOSE 5000
CMD ["python", "app.py"]

# Procedure
Step 1: Set Up the Project Folder Create a new directory named myapp in your home directory:

Bash
mkdir -p ~/myapp
Step 2: Save the Files Save the app.py and Dockerfile code listed above directly into the ~/myapp directory. Make sure the Dockerfile does not have a .txt extension.

Step 3: Build the Docker Image Navigate into your project folder and compile the application into an image named flaskapp:

Bash
cd ~/myapp
docker build -t flaskapp .
Step 4: Run the Docker Container Launch the container and forward port 5000 from your host machine to the container:

Bash
docker run -p 5000:5000 flaskapp
Step 5: Test the Application Open a web browser and navigate to http://localhost:5000 to verify that the Flask web application is loading successfully.

# Conclusion
In this practical, a Python Flask web application was successfully containerized. The standard workflow of writing a Dockerfile, building an immutable image, and deploying it as a running container was demonstrated. This process highlights how containerization creates a portable, consistent environment that behaves identically regardless of the host system's configuration.
