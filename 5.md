# Pushing Docker Image to the Registry and Understanding Dockerfile Structure
# Aim & Objectives
To understand how container registries store and share Docker images, and to learn how to build, tag, push, and structure images using a Dockerfile.

Understand the role of Docker Hub in application deployment.

Manage local images using the docker images command.

Learn the correct syntax to tag and push images to a remote registry.

Analyze the core commands that make up a standard Dockerfile structure.

# Theory
A container registry is a centralized storage system used to share and manage container images. Docker Hub is the most popular public registry.

The standard workflow moves from a local environment to the cloud:

Build/Find a local image.

Tag it with your registry username.

Push it to Docker Hub.

Verify it via the web interface.

A Dockerfile uses a layered architecture where each instruction creates a new layer in the final image, ensuring environments are fully reproducible and portable.

# Procedure
Part 1: Registry Operations
Step 1: Check Local Images List all existing images on your machine to find the one you want to upload:

Bash
docker images

Step 2: Tag the Image To upload an image to Docker Hub, it must be tagged with your exact Docker Hub username.

Bash
docker tag local-image:latest username/imagename:v1.0
(Alternatively, you can tag it directly during the build phase using docker build -t username/imagename:v1.0 .)

Step 3: Push to Docker Hub Upload your tagged image to the remote repository. If no version tag is provided, Docker defaults to latest.

Bash
docker push username/imagename:v1.0

Step 4: Verify the Upload Log into hub.docker.com through a web browser to confirm your image appears in your repository dashboard.

Part 2: Understanding the Dockerfile Structure
A standard Dockerfile uses a straightforward 6-step skeleton:

FROM – Defines the base operating system or runtime layer (e.g., python:3.10-slim, node:18, nginx).

WORKDIR – Sets the active working directory inside the container for any subsequent commands.

COPY – Transfers files from the host machine to the container (e.g., COPY . . copies everything from the current local folder to the current container folder).

RUN – Executes commands during the image building phase, such as installing packages (e.g., RUN pip install flask or RUN npm install).

EXPOSE – Documents the network port the application listens on inside the container (e.g., EXPOSE 8080).

CMD – Specifies the actual command that executes only when the container starts running (e.g., CMD ["node", "server.js"]).

Dockerfile Configuration Examples
Example 1: Python Flask Application
Dockerfile
FROM python:3.10-slim
WORKDIR /app
COPY . .
RUN pip install flask
EXPOSE 5000
CMD ["python", "app.py"]
Explanation: Starts with a lightweight Python image, sets /app as the active folder, copies project files, installs the Flask library, opens port 5000, and launches app.py on container startup.

Example 2: Node.js Application
Dockerfile
FROM node:18
WORKDIR /app
COPY . .
RUN npm install
EXPOSE 8080
CMD ["node", "server.js"]
Explanation: Starts with a Node.js version 18 environment, sets /app as the active folder, pulls project code inside, runs npm install to download node dependencies, documents port 8080, and runs server.js when launched.
